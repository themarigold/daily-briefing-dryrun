Pick up where you left off.

daily-briefing is a morning briefing for developers who work with AI coding assistants. It reads your local git history and tells you where you left off, what you did, and what to do next, written by the AI you already use and ready when you first sit down.

A desktop app for macOS and Linux, and a command-line tool for macOS, Linux and (experimentally) Windows. No account, no server: it runs on your machine.

Privacy

daily-briefing is local-first and has no telemetry of its own: no analytics, no usage or crash reporting, no account, and no server of its own. It reaches the network in five places, and no others. The AI provider you choose: the prompt, built from your commit subjects, short hashes and dates, the names of changed and uncommitted files, repository and branch names, and stash messages, goes to that provider under its terms, through the AI tool you configure (provider.cli) or as one HTTP(S) request per attempt to the API endpoint you set (provider.api), which is encrypted only if that endpoint is https:// (a plain http:// endpoint that is not on your own machine sends the prompt and your API key unencrypted). Point it at a local model and the prompt never leaves your machine. A connectivity check before it generates, and, on macOS, each time the desktop app opens: a TCP connection to the hosts in networkProbeHosts (by default 1.1.1.1 and 8.8.8.8, or your API endpoint), opened and closed with no data sent, which you can turn off. GitHub, only if you turn on the update check or ask for one: a single anonymous request to api.github.com for the latest release, carrying the version number, and after the first answer GitHub's own cache tag, and nothing about you or your code. Your repository's own remote, only in a partial clone (one made with --filter, or by scalar clone): the tool never runs git fetch, pull or push, but when it reads such a repository's history, git itself downloads the file contents it is missing from that remote, with your usual git credentials. A normal clone never does this. Otherwise git only reads your local repositories. It can also start helper programs your own git configuration names (a diff driver, an fsmonitor hook, or a filter), and what those contact is up to them. And the Bun runtime the engine is built with, only if Bun itself crashes: on macOS and Windows it can send Bun's team a crash trace (Bun's version, your platform, an internal stack trace, the crash reason and which Bun features were used; no source code or personal information, per Bun) to bun.report. The desktop app and the macOS schedule turn this off; for a run you start from a terminal, or the experimental Windows schedule, set DO_NOT_TRACK=1 to turn it off. The full privacy notes
